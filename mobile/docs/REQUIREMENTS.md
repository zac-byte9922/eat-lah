# Eat Lah 手机 App：当前有效需求

本需求覆盖仓库历史设计中的网页技术路线。应用使用 React Native + Expo + TypeScript + Expo Router，直接渲染原生组件，支持 Android 和 iOS；不采用 Next.js，也不将旧 HTML 嵌入 WebView。

## 第一阶段实现范围

- 极简白色、绿色点缀、圆角卡片；适配手机宽度、安全区和输入键盘。
- 首次使用四步设置：新加坡邮编、厨具、冷藏/冷冻条件、每周预算、单餐热量参考、过敏、忌口和味道偏好。
- 首页先选早餐/午餐/晚餐，再选“我想做点 / 今天省点事”。
- 做饭：清淡 / 普通 / 罪恶 / 减脂 / 一键推荐；单张原生卡片左滑跳过、右滑保留，支持按钮替代手势、撤销跳过和收藏。
- 主食后可加一道菜和一份小食，均可跳过；螺蛳粉等支持可选加料。
- 省事：在家吃 / 出去吃 / 点外卖。外食和外卖仅记录，不发起交易或扣家里库存。
- 中英文购物清单合并多餐需求，优先分配可用库存。按用户输入的真实包装含量向上取整，实际买到的包数由用户确认；价格未知留空。
- 确认购买后按批次入库；需要核对包装有效期、过敏原和储存状态。未核对、过期、丢弃或储存不兼容的批次不参加扣减。
- 新手分步烹饪页面；完成当天餐次后记录日志并按用量 FEFO 扣减；库存不足不允许伪造完成。重复点击不重复扣减，可撤销恢复原批次。
- 3–7 天早午晚菜单规划，保留已完成记录；收藏、本机历史、临期及需检查库存的 App 内提醒。
- AsyncStorage 本机持久化，写入串行化、失败不发布状态、损坏资料保留；提供系统分享导出。
- 保留 Supabase 接口边界，未来通过 Auth、RLS 和事务 RPC 接入云端。

## 数据边界

迁移了旧原型 58 项原创演示条目及 52 项双语食材，不是 58 道已审核完整食谱。未迁移估算商品价格和包装规格；食谱一律标记 draft、original-demo、estimate，sourceUrl 为 null。未导入第三方作品正文、图片或视频。热量、时间和步骤尚需编辑与厨房实测；加工食品以真实包装为准。

## 本阶段不宣称完成的功能

Supabase 登录和跨设备同步、服务端用户隔离、真实商品/SKU/门店/价格、营养审核、系统通知推送、账号数据迁移、应用商店上架、300 道审核食谱及 200 项真实商品目录。它们仍属于后续里程碑。

本地没有多用户登录，不能将路由设置拦截称为服务端认证或访问控制。原生编译和组件测试不能替代 Android/iPhone 真机手势、键盘、字体、可访问性和生命周期测试。
